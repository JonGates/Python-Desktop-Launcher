# Project Launcher · C# 版设计

## 目标与约束
每个现有 Python 项目获得自己的 Windows 桌面壳，不是 Web 服务，不执行 Python GUI。
保留 schema_version: 1 配置（以随包 legacy-v1.yaml 和上一版 CONFIG.md 为依据）。
独立运行页、项目终端、环境管理、项目设置。可视化参数编辑优先，完整 YAML 为高级入口。
用户要求直接实现并完整打包：本次按已确认功能范围连续实现，不重新询问已经回答的产品方向。

## 实现决策
- .NET 10 / WPF，全部界面原生 XAML；仅 YAML 解析使用 YamlDotNet 18.1.0。
- 明暗两套语义色，宽留白、圆角卡片、自绘矢量图标；不依赖额外字体、浏览器或 WebView2。
- Core: 配置、参数、环境计划、进程执行、持久化、VT 屏幕；Windows: ConPTY/JobObject；Desktop: WPF；CLI: 独立控制台伴随程序。
- 项目环境必须明确存在；不自动回退系统 Python。壳自身不依赖项目 Python。
- 初始化/同步依赖必须由用户主动触发；配置未信任时先确认。绝不自动下载并执行项目代码。
- 任务使用 argv，不将表单值拼接进 shell；终端和任务分离；日志/预设过滤已标记密码。
- 关闭时确认并清理归属进程；设置变更必须先停止任务并关闭终端。
- 内置终端支持常用 VT 操作与持久会话，但不承诺 Windows Terminal 的全部 TUI/IME 兼容；提供系统终端和中文输入行。

## 不在本次范围
自动分析任意 Python 源码并执行其入口探测、自动强制修复依赖、程序自身在线更新、代码签名、完整 IDE、任意 TUI 100% 兼容、跨平台桌面 UI。

## 验收
读取旧配置；表单生成正确参数；外部文件修改冲突可检测；初始化前不能启动业务；失败/超时/停止有退出状态；终端 cd 和变量保持；配置秘密不持久化；复制安装只新增壳文件；明暗主题可切换。
需要 Windows + .NET SDK 10 才能完成编译和 WPF / ConPTY 验收。未执行的测试明确标记，不用静态检查冒充编译。
