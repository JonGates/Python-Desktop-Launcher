# 中英国际化、紧凑布局与快速使用文档设计

日期：2026-09-23。状态：待用户审核；本文不是已实现功能说明。

## 目标与范围

保留 Windows 原生 WPF、单项目、多启动动作结构。修复启动动作设置页底部多余留白，提供完整简体中文与英文界面，并让新用户通过双语 README 快速开始使用。沿用现有环境绑定、参数弹窗、动作列表与独立配置区域。

不新增项目管理器，不改变配置执行语义，不发布 GitHub Release，不自动推送 Git。完成实现及验证后生成便携 EXE 并提交本地 Git。

## 1. 收紧设置页底部

当前 ActionWorkspace 的空错误 TextBlock 仍参与布局，并叠加 SettingsView 保存栏的顶部间距。错误为空时将整行折叠，有错误时才显示提示；保存栏顶部外边距调整为 10 DIP，分隔线与按钮之间保留 10 DIP。正常状态下卡片至分隔线不再保留空错误行。

保持底部保存操作固定可见，左右列表与配置区域独立滚动。错误出现时允许编辑区缩小，不遮挡保存按钮。不通过写死卡片高度解决留白。在 1060×700、1360×900、深浅主题及高 DPI 下检查。

## 2. 侧栏与语言交互

- 移除下方“当前项目”卡片；顶部项目名称和说明继续展示用户配置。
- 原“本地工作空间”位置改为紧凑语言选择器，选项固定显示“简体中文”和“English”。
- 同一工具区保留打开项目目录的小图标、主题和帮助按钮；图标提供随语言更新的提示与无障碍名称。
- 保留项目版本状态栏和 GitHub 链接，中文显示“Python-Desktop-Launcher 官网”，英文显示“Python-Desktop-Launcher Website”。
- 首次没有用户偏好时，系统 UI 语言为中文则用简体中文，其他语言用英文。之后优先使用用户选择。

语言偏好属于启动器用户，不属于业务项目。存储在 `%LOCALAPPDATA%/ProjectLauncher/preferences.json`，字段使用稳定语言标识 `zh-CN` / `en-US`。在首次绑定窗口出现前读取。采用原子写入；文件损坏时保留原文件、不破坏启动，回退系统语言并提供可理解提示。保存失败时本次切换仍生效，同时提示未能记住选择。

切换语言不写 launcher.yaml、不改变配置脏状态、不重建主窗口、不终止或重新启动任务和终端。编辑中的参数值、未保存的动作配置、选中动作、展开状态和日志保留。

## 3. 国际化边界与实现方向

采用稳定资源键、两套文本资源和可观察的语言服务；不采用按中文字符串全局替换，也不通过重新加载整个视图切换语言。XAML 绑定可更新资源，代码创建的控件使用同一服务。切换事件在 WPF Dispatcher 上更新显示文本，相关订阅随视图释放。

资源及格式化逻辑不依赖 WPF；Desktop 层负责 WPF 绑定适配。Core 继续不能引用 WPF。选择项的值与显示文本分离，例如 Python 脚本/模块等显示可翻译，但配置标识、参数类型、动作 ID 和命令数组保持稳定。

覆盖：首次绑定、主窗口导航、运行页、终端工具栏、环境管理、设置页、参数编辑弹窗、确认弹窗、工具提示、无障碍标签、配置验证和启动器产生的错误与状态。带变量的文本使用资源格式参数，不拼接固定中文片段。

启动器已知诊断使用稳定键及参数，在呈现边界格式化；未知系统异常保留原始技术详情并提供本地化说明。不能声称第三方或操作系统异常详情均可翻译。正在显示的启动器状态保留结构化来源，可随语言变化刷新。历史记录兼容已有内容，无法明确识别的旧文本原样显示。

以下内容绝不翻译或改写：项目/动作/参数自定义名称及说明、输入值、路径、环境变量、YAML 键、原始命令、Python 业务日志和终端输出。切换显示语言不影响参数解析和 argv 生成。

资源缺失时回退英文；测试必须检查两套资源键及格式占位符一致，不能依赖回退掩盖漏译。

## 4. 双语 README

README.md 使用英文，README.zh-CN.md 使用中文，顶部互相链接。两份内容和操作步骤同步：一句话定位、真实原生 WPF 截图、快速使用、常见问题、开发文档链接。

快速使用围绕实际路径：取得便携包、把 Launcher.exe 放到项目目录、启动后使用已有 launcher.yaml 或绑定已有 Python 环境、添加启动动作和参数、保存并运行。明确启动器本身独立于 Python，但业务任务需要有效项目环境；缺少环境不会自动使用系统 Python。安装/同步依赖需用户显式确认。

写文档时核实实际可用的发行渠道。没有公开 Release 时不放虚假下载按钮，不声称已有公开二进制；明确提供本地构建入口与实际分发方式。开发、测试及完整配置说明链接到现有 docs，不堆在快速开始正文里。

截图来自真实 WPF 运行，使用中性示例项目，不暴露用户项目路径或秘密。不使用 HTML 模拟图冒充原生截图。徽章只表示可核实的平台、技术、许可证及预览状态，不虚构下载量、测试或发布结果。

## 5. 验证与交付标准

先增加失败测试，再实现。测试至少涵盖语言选择优先级、持久化失败/损坏回退、资源完整性、参数格式化、英文与中文布局，以及切换时草稿/输入值/动作选择/进程标识不变。

UI 测试使用稳定控件名，不能依赖宿主系统语言；固定中文基线并添加英文场景。检查初次绑定和参数弹窗、长英文按钮、空错误行折叠、有错误时显示、底部按钮不裁切。验证业务输出及用户文本没有被翻译。

执行完整 Core、Windows 可执行规格测试，以及 tools/Test-Windows.ps1 的 WPF 渲染检查；运行 Python 示例与静态检查。生成便携 EXE 后执行 tools/Test-Portable.ps1。更新测试报告，准确记录实际计数、哈希和未做的手动 DPI/IME 验收，不把自动渲染等同于完整人工验收。
