# 安全与操作边界

这个启动器是本机进程的用户界面，不是安全沙箱、容器或权限隔离器。打开未知项目可以阅读配置；确认运行 / 初始化 / 终端以后，会以当前 Windows 用户的权限执行对应代码和安装命令。不要用管理员身份作为默认运行方式。

## 执行信任

GUI 第一次执行一份配置时要求确认，并保存配置哈希；配置发生变化后重新确认。磁盘修改后未重新加载会拒绝执行。该确认不是代码签名，也不追踪全部 Python 文件 / requirements 内容，不能证明第三方项目安全。

自动发现只看有限候选文件名与依赖标记，不导入 Python 模块、不执行 --help、不自动扫描执行自定义入口。识别到 main.py 不代表它是正确入口，用户必须核对。

业务命令使用 argv 与独立环境映射。普通 `&`、`;`、空格作为数据，不经 Shell 解释。配置里显式加入 cmd、PowerShell、Python -c 时，代码本身仍由配置者负责，不应拼接未校验输入。

## 环境选择不是绝对限制

裸 python / pip 使用项目解释器；缺少所选 `.venv` 则拒绝执行。受保护环境变量不能由表单 / runtime.env 覆盖。该强制映射针对 GUI / CLI 的参数化动作；交互 Shell 的命令解析由 Shell 自己处理。uv 项目可能没有 pip，此时终端里请用 `python -m pip` 或 `uv pip --python ...`，避免系统 PATH 上的同名工具。仍允许开发者指定绝对程序路径，终端用户也可主动修改 PATH、激活别的环境或运行绝对路径程序。

PATH 清理不能阻止项目中的恶意模块、sitecustomize 或原生扩展。解释器检查本身也会运行项目解释器，因此同样需要信任确认。

## 敏感值

password / secret 表单运行值不写入上次参数和预设，命令预览隐藏已知值。运行日志流对本次已知敏感字符串进行跨块替换；这只能处理精确匹配，不能识别编码、分割、变形、未知令牌或业务产生的新敏感数据。

GUI 任务 stdout / stderr 的脱敏与交互终端是两条不同链路。终端作为真实 Shell 不承诺替用户隐藏所有输出 / 输入，Shell 自己可能保存历史。CLI `--set token=...` 也可能记录在调用方历史和 OS 进程列表里；敏感操作建议使用 GUI 密码框与 env 绑定。

YAML default、runtime.env、argv 是明文，不能当密码保险箱。配置备份、之前的日志、运行历史也可能保留过去未标记为敏感的内容，不做回溯清洗。使用秘密之前先确定日志与业务脚本的处理方式。

## 终端保护

多行粘贴需确认；粘贴会滤除 ESC 等危险控制字符。OSC 52 不自动访问剪贴板，链接不自动打开。用户仍可正常键入或粘贴有风险的系统命令，程序不会成为危险命令过滤器。

任务日志和终端滚动缓冲区有上限，避免输出无限占用内存。单次任务磁盘日志约 10 MB、保留最多 100 条日志；超过上限会提示截断，不停止业务任务。终端显示队列严重积压时重置显示并告警，不声称保存了所有交互输出。

## 停止与写入

停止 / 超时会终止归属进程，可能留下半成品。不会假装暂停业务函数，也不保证任意外部后台服务都被终止。业务代码需自行实现原子写入、恢复点和事务一致性。

配置保存先备份再原子替换，检查已有文件哈希；不等于分布式文件锁。项目安装不覆盖同名 EXE、配置和源码。已存在的不完整环境不自动删除。不要关闭这些保护以“自动修复一切”。

## 诊断与分发

壳没有遥测 / 云端回传功能。崩溃记录在当前用户 LocalAppData，日志在项目内；异常文本可能含本地路径，分享诊断前自己检查。

源码未附编译通过的 EXE、数字签名、稳定兼容声明。正式使用前完成 Windows 验收并审查依赖，正式分发时保留许可证 / notices，建立自己的签名与升级流程。
